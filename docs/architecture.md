# NAS Core Demo 架构说明

## 1. 目标

这个 demo 用来演示 NAS 核心能力的基础分层，而不是直接实现生产级能力。

它重点回答 4 个问题：

1. 核心模块应该怎么拆
2. 高风险操作如何任务化
3. 前端如何和后端状态同步
4. 后续怎么替换成真实系统调用

## 2. 总体架构

```text
Web Console
  -> HTTP API
    -> Task Engine
      -> Recovery Service
      -> Network Service
      -> VM Service
        -> In-Memory Store
```

## 3. 模块边界

### Recovery Service

负责：

- 快照管理
- 文件恢复
- 卷回滚
- 恢复结果写入

当前 demo 中的恢复动作是模拟执行，但任务模型、步骤跟踪和结果记录与真实实现保持一致。

### Network Service

负责：

- 网卡信息查询
- 配置前校验
- 配置任务执行
- 连通性探测模拟
- 失败回滚

这个模块的设计重点是：

- 危险操作必须任务化
- 必须能回滚
- 必须保留变更前状态

### VM Service

负责：

- VM 列表
- VM 创建
- 启停控制
- 资源状态维护

当前使用内存态 VM 数据，后续可以替换为 `libvirt` 适配器。

## 4. 任务引擎

任务引擎是整个 demo 的核心抽象。

所有高风险操作都必须走统一接口：

- 创建任务
- 标记运行中
- 记录步骤
- 成功结束
- 失败结束
- 必要时标记已回滚

这样做的好处：

- 前端能统一展示任务进度
- 后端能统一审计
- 后续容易接入重试、告警、取消

## 5. 状态模型

当前使用单进程内存存储，便于理解结构。

主要数据域包括：

- `tasks`
- `recovery.snapshots`
- `recovery.recoveries`
- `network.interfaces`
- `network.history`
- `vm.vms`

真实项目中建议拆为：

- 配置数据库
- 审计数据库
- 宿主机实际状态采集
- 任务执行持久化

## 6. 真实项目替换建议

### 数据恢复

把下面动作替换为真实能力：

- 创建快照
- 浏览恢复点
- 恢复文件
- 整卷回滚

可接入：

- `Btrfs`
- `ZFS`
- `LVM`

### 网络配置

把模拟网络配置替换为真实系统能力：

- `ip addr`
- `ip route`
- `bridge`
- `bond`
- `vlan`

注意：

- 一定要先缓存原配置
- 应用后必须做探活
- 探活失败必须自动回滚

### 虚拟机管理

建议后续接入：

- `QEMU/KVM`
- `libvirt`

需要继续扩展的能力：

- 模板
- 快照
- 克隆
- 导入导出
- 控制台接入
